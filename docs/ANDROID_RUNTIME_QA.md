Среда: Android Emulator 37.2.13, x86_64 API 30, программный TCG без `/dev/kvm`, 2 виртуальных CPU и 2 ГБ RAM. Снимок приложения 800×480. Итоговый запуск: `-gpu host`, `DISPLAY=:98`, `LIBGL_ALWAYS_SOFTWARE=1`; Mesa 25.0.7 / llvmpipe LLVM 19.1.7, OpenGL ES 3.1. Полный лог эмулятора сохранён в архиве проверки.

При первоначальном запуске старый SwiftShader 4.0.0.1 выдал `Fragment shader active uniforms exceed GL_MAX_FRAGMENT_UNIFORM_VECTORS (261)`. GLES-запрос внутри Android подтвердил предел 261. Независимый минимальный контроль на точной библиотеке SwiftShader воспроизвёл ошибку учёта неиспользуемого UBO; тот же шейдер успешно линкуется в Mesa. Два диагностических изменения бюджета света не устранили сбой. Итоговый проход выполнен на исходном APK с исходными настройками, с заменой только рендера эмулятора. [Результаты независимого контроля шейдера](qa/gles-uniform-control.txt); код контроля и Android GLES limits сохранены в архиве проверки.

Из-за программной эмуляции Android показывал собственный диалог `System UI isn't responding`; нажата «Wait» по координатам, вычисленным из UI XML. `am start -W` завершился тайм-аутом ожидания, после чего отдельно подтверждены запуск main loop и фактический экран. Это не считается аварией игрового процесса. Неисправный shader cache прежней тестовой установки потребовал очистки; прогретая ОС и AVD сохранены.

Полный игровой переход «Новая игра → Россия → город», физическое Android-устройство и FPS не проверены. Тест подтверждает установку, старт движка, главный экран и 3D-рендер исходного APK в указанной среде.
